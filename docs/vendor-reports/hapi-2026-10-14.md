# HAPI 上报单：Gemini（alice/gemini-3.8-flash）三个问题

日期 2026-10-14（UTC+8）。接口 `POST https://hapi.hc11.org/v1/messages`，模型 `alice/gemini-3.8-flash`，Anthropic 形态请求，非流式。以下均为最小复现，不含钥匙。

## 1. 最后一条 user 消息只有 tool_result → 400001

```json
{"model":"alice/gemini-3.8-flash","max_tokens":256,
 "tools":[{"name":"get_weather","description":"查天气","input_schema":{"type":"object","properties":{"city":{"type":"string"}},"required":["city"]}}],
 "messages":[
  {"role":"user","content":"北京天气?"},
  {"role":"assistant","content":[{"type":"tool_use","id":"toolu_01X","name":"get_weather","input":{"city":"北京"}}]},
  {"role":"user","content":[{"type":"tool_result","tool_use_id":"toolu_01X","content":"晴 18 度"}]}]}
```

- 现象：返回 `Invalid request parameters`（400001）。末条 user 里**多补一个任意文本块（哪怕空串）**即正常回答。
- 请求号：`ef8c52ba-d9e0-49dc-921e-8f900389b925`（14:32:57）、`b431a5b5-d4b5-4d72-8285-d555bd5beb64`（14:33:49）。
- 真实客户端（Claude Code 第 2 轮）：`96be2b6b-d557-49b1-bad1-6ce5429bdd7f`、`831ddc1d-201d-4173-a284-92134352cd81`、`d424ccfe-c6c4-4448-a3a6-eee923114eaf`（13:49–13:50）。
- OpenAI 形态同样：chat 末条 `role=tool` 触发同一错误。
- 影响：所有带工具调用的 Agent（Claude Code / Codex 等）第 2 轮起全部失败，即「hi 能回、一用工具就挂」。

## 2. 工具 schema 的 `required` 含 `properties` 里没有的字段 → 透出 Google INVALID_ARGUMENT

tools 的 `input_schema.required` 里放一个未在 `properties` 定义的名字（例 `["zzz"]`）。
- 请求号：`f54e20aa-f30b-4505-9fa2-52dfcfb186cf`（14:32:59）、`0108e187-a25c-420e-9540-fd682944704d`（14:33:53）。
- 期望：转换层清理未定义的 required（Anthropic / OpenAI 对这种写法都放行，手写 MCP 工具里很常见）。

## 3. 上述错误都以「HTTP 200 + `{"type":"error",…}`」返回

状态码为 200，调用方（网关、SDK）当成功处理，不会重试也不会换渠道，客户端拿到「不是 Message 的 JSON」后才报错。期望：错误用真实 4xx/5xx。

## 我们这边的临时处理

渠道适配层（本仓）对 hapi 的 Gemini 渠道：补文本块（1）、去掉未定义 required（2）、非流式 200+错误改回 502（3）。HAPI 修复后我们会按 `docs/adapters.md` 里各规则的「何时可删」撤掉。
